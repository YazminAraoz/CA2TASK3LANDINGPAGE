Phase 1: Real-World Foundation

Initial Context & Human Insights

Operations: Tom Kehoe runs the garage with mechanics servicing around 25 cars a day. Bríd runs the office.

The Bottleneck: The garage receives roughly 60 phone calls per day for vehicle updates. When Bríd is busy, a mechanic has to stop working to answer them, which costs about 90 minutes of mechanic time per day.

Forgotten Vehicles: Cars waiting on parts often get overlooked, sometimes sitting for 5 days or more with no updates communicated to the customer.

Target Market: Independent owner-run garages (who would pay for a generic version of this solution).

Phase 2: Functional Scope

Required System Views & UX Constraints

  • Workshop View: Needs to run on a wall tablet with greasy hands. Features large touch targets, zero typing, and 1-tap stage progression (Booked in, Being checked, Waiting for parts, Being fixed, Ready to collect). Shows who each car is assigned to.
  • Customer View: A secure status screen accessed strictly via job number and vehicle registration. Displays only that specific car's stage and a short plain-English note, keeping all other customer data private.
  • Office View: Groups cars by stage, flags cars waiting for parts for more than 2 days in red, and tracks ready-for-collection counters.
Phase 3: Exact Prompts & Gemini Iterations

My Exact Prompts Used with Gemini

I used Gemini and polished the prompt, committing a few times until I got the result I wanted. I learned from this exercise that AI gives you general info and sometimes due to communication misinterprets things.

Prompt 1: Core App Foundation

Build a single-file web app (HTML, CSS and JavaScript in one file, no external libraries, works on a phone) called BAY WATCH, for Kehoe's Garage, Enniscorthy, Co. Wexford...

Prompt 2: Access Control & Mechanic Reassignment

Change it so if a customer access only can view the customer portal. As it is a demo, the password and log in is showing and disposable. Make a part with person assigned only on the workshop part. Make it more easy to assign and reassign mechanic. Think these will be people with greasy hands and busy environment. Also make it more design savy.

Prompt 3: Landing Page & SaaS Structure

Build index.html: a landing page that sells the generic version of BAY WATCH, not to Kehoe's Garage and not to everyone - to your Task 1 niche (Rural independent owner-run garages in Leinster)... Include headline, problem quotes, 3-step guide, pricing assumption (€199 setup + €59/month), and waiting list form.

Prompt 4: UX & Tablet Mockup Refinements

Make it more UX friendly. Exclude any task. Make the app from before like a real landing page for these service. Add more colour and cool design car brand inspired, make it mobile first. Eliminate testimonial. Make it true to the app designed. Make the model from tablet interactive and the same as demo with interaction but not dynamic sizing. Add contact formulation like before.

Key Takeaway

Iterating closely with AI required clear human insights regarding the physical realities of a rural independent garage. Refining prompts multiple times ensured the final artifact matched exact workflow and UI expectations without unnecessary fluff.
